Can a compiler refuse to clone a qubit?

A quantum simulator written in cancho: 17 gates, noise (sampled and exact), OpenQASM input, and a type checker that refuses to clone, drop or reuse a qubit. Built to find out what a language with linear types catches in quantum code, and to say plainly what it misses.

What it can do

  
Everything named here is run by the page’s build script before it is written down, and the numbers under Measured come from the same runs.

  

    
17 gates
One qubit: H, X, Y, Z, S, S†, T, T†, Rx, Ry, Rz, P. Two: CNOT, CZ, controlled phase, SWAP. Three: Toffoli. Angles are exact fractions of π.

    
Pure states, measured or sampled
Up to 20 qubits (16 MiB at 20). Seeded measurement with collapse, and sample N to draw outcomes without collapsing. The same seed gives the same bits on every build.

    
Noise, two ways
5 channels: bit flip, phase flip, depolarizing, amplitude damping, two-qubit depolarizing; asymmetric readout error; a model that adds depolarizing noise after every gate, with its own rate per qubit and per pair, or read from a device-style profile file; idle decay (T1, T2) while a qubit waits or a gate runs. Sampled runs (any size; the average is the physics) or the exact density matrix (up to 10 qubits).

    
Two input formats
A plain-text circuit format, and OpenQASM 2.0 (angles that are multiples of π; 20 circuits cross-checked with Qiskit’s own parser).

    
Algorithms
Bell and GHZ states, teleportation, the quantum Fourier transform, Grover search, Bernstein–Vazirani and Deutsch–Jozsa, all as circuits with a known answer.

    
A type checker for qubits
A Qubit cannot be copied or dropped; only measure ends one. 12 refusal fixtures, and 7 pinned cases the checker still misses.

  






  
What the type checker found

  
The idea: qubits are linear resources. The test: write the simulator, then try to write the mistakes, and see which ones the checker stops. No compiler change was made.

  

    
No-cloning is a type error
A Qubit is a res: it cannot be copied, cannot be dropped, and only measure ends it. Cloning, dropping, measuring twice and escaping a borrow are all refused by rules cancho already had.

    
Reproducible to the byte
80 circuits. Each runs six ways (interpreted and compiled; Cranelift and LLVM; aarch64 under emulation), three for the 20 density-matrix circuits, which are interpreted only. The outputs are identical, and their hashes are checked in. Adding noise, QASM and the density matrix did not change one earlier hash.

    
Gaps, stated up front
A repeated qubit in a multi-qubit gate (CNOT, SWAP, Toffoli with one qubit twice) is not refused at check time: it is accepted and stops at run time. A Qubit can also be written by hand from any module. The gallery lists both, and what would close them.

For humans

  
What this is, what you can do with it today, and how far to trust it.

  

    
What you can do

      
    
        
  • Run a circuit: a few lines (h 0, cx 0 1, rz 2 1 4) and read the amplitudes, or draw outcomes with sample 1000.
    • 
        
  • Add noise (depol 1 1 4, readout 1 20, or a model for every gate) and either sample it or ask for the exact density matrix (dm 2).
    • 
        
  • Feed it OpenQASM 2.0 from Qiskit, or the algorithms in tests/diff/.
    • 
        
  • Write a typed program with Qubit values and see the checker say no when you clone one.
    • 
        
  • Check the numbers yourself against Qiskit, and the bytes against the checked-in hashes.
    • 
      

    
How far to trust it

      
    
        
  • Amplitudes and density matrices match Qiskit 2.6.1 to 9.659e-15 on 80 circuits (the gate is 1e-12). Up to 20 qubits (10 for the density matrix).
    • 
        
  • Sampled noise is checked as an average: thousands of runs against the exact density matrix, not run by run.
    • 
        
  • It is a research prototype: one reference implementation, one compiler revision, one machine plus emulation.
    • 
        
  • It is not fast and not a rival to Qiskit Aer or qsim, and does not try to be.
    • 
      

  

  
The input is plain text, one operation per line, so a circuit can be hashed and kept beside its reference output. Sampled noise and sampling:


n 3        # three qubits
h 0
cx 0 1     # a Bell pair
depol 1 1 4  # depolarizing noise on qubit 1, probability 1/4
model2 1 50  # or: noise after every two-qubit gate from here on
ry 2 1 3   # rotate qubit 2 by pi/3
seed 7     # the sampler is seeded: same seed, same bits
readout 1 20 # report each measured bit flipped, 1 time in 20
coher 0 50000 70000  # qubit 0: T1 50 us, T2 70 us (nanoseconds)
wait 0 20000  # ...and it idles for 20 us, so it decays
sample 1000  # 1000 outcomes, counted per bit string
m 0        # or measure qubit 0 and collapse the state

  
The same noise, exactly (dm in place of n, up to 10 qubits): one run prints the density matrix, and purity, trace and probs ask for its properties.


dm 2
h 0
cx 0 1
depol 1 1 4
purity     # prints purity 0.5833...

What not to get wrong

      
    
        
  • Do not fix a refusal by copying a qubit. It cannot be copied; qubit.measure ends it.
    • 
        
  • CNOT on one qubit twice compiles. It is a known gap, not a bug in your setup; do not report it as a refusal.
    • 
        
  • Qubit { ... } can be written by hand from any module. That is a known gap too.
    • 
        
  • Do not edit tests/golden/ to make a check pass.
    • 
        
  • The aarch64 result is emulation, not hardware.
    •

Ask your coding agent to try it

  
Paste this into Claude Code, Codex or any agent that can run commands. It builds the compiler at the measured revision, runs the checks, and has the agent watch a clone get refused.

  

    
prompt raw

    
Install cancho-quantum and try it on one small circuit. Work in a new empty directory, keep every path free of spaces, and never use sudo. Run steps 2 to 5 in one shell session. Report honestly; do not retry a failing command in a loop and do not edit the repository to make a command pass.

1. Check that `git`, `cargo` (Rust, via rustup), `python3` and a C linker (`cc`) exist. If one is missing, stop and tell me which; do not install system packages on your own.

2. Get the cancho compiler at the revision this project was measured against, and build it:
   git clone https://github.com/alpibrusl/cancho.git
   git -C cancho checkout 3fa3fbb
   (cd cancho && cargo build -p cancho)
   export CANCHO="$PWD/cancho/target/debug/cancho"

3. Get the simulator:
   git clone https://github.com/alpibrusl/cancho-quantum.git
   cd cancho-quantum

4. Run the checks that need no network after the clone:
   python3 scripts/check_types.py          # every line must say ok; ends "24 of 24 fixtures behave as stated"
   Then, only if you may install Python packages into a virtual environment (python3 -m venv .venv && . .venv/bin/activate && pip install qiskit numpy):
   python3 scripts/check_diff.py           # amplitudes against Qiskit; ends with the worst error, which must be under 1e-12
   python3 scripts/check_qasm.py           # OpenQASM files read by Qiskit's parser and by qsim agree
   python3 scripts/check_profile.py        # the device-style noise profile converter and its use, against Qiskit
   python3 scripts/check_noise.py          # noisy runs averaged over 4000 seeds match an exact density-matrix calculation (about 40 s)
   python3 scripts/check_determinism.py    # six builds per circuit must give identical bytes (omit --arm64 unless qemu-aarch64 is installed)

5. Try the simulator and the checker on your own input:
   $CANCHO build src/*.cho --std -o qsim
   printf 'n 2\nh 0\ncx 0 1\n' | ./qsim     # a Bell state: amp 0 and amp 3 are 7.071067811865475e-1
   cat tests/qasm/qft4.qasm | ./qsim | head -3   # the same simulator reading OpenQASM 2.0
   printf 'dm 2\nh 0\ncx 0 1\ndepol 1 1 4\npurity\nquiet\n' | ./qsim   # exact noise; prints purity 5.833333333333328e-1
   printf 'dm 1\ncoher 0 50000 70000\nx 0\nwait 0 20000\nprobs\nquiet\n' | ./qsim   # T1 decay: prob 1 is exp(-0.4) = 6.703200460356392e-1
   printf 'n 3\nh 0\nh 1\nh 2\nseed 1\nsample 100\n' | ./qsim | head -8   # 100 samples, counts per outcome
   Now make a program that clones a qubit and watch it be refused. Copy tests/reject/clone_qubit.cho, read it, and run:
   $CANCHO check src/complex.cho src/state.cho src/gates.cho src/profile.cho src/measure.cho src/noise.cho src/qubit.cho tests/reject/clone_qubit.cho --std ; echo "exit $?"           # expect exit 1
   $CANCHO check src/complex.cho src/state.cho src/gates.cho src/profile.cho src/measure.cho src/noise.cho src/qubit.cho tests/reject/clone_qubit.cho --std --output json          # the rule is "linear-use-after-move"
   Do not fix the refusal by copying the qubit: it cannot be copied. A qubit is ended by `qubit.measure`.
   Then run tests/accept/same_handle_cx.cho (see its header) and report what happened: it compiles and then stops at run time. That is a known gap, not a bug in your setup.

6. Tell me, briefly:
   - the exit code and the first line each command printed in step 5;
   - whether step 4's checks passed, and the last line each printed;
   - anything that failed, with the exact error.
Docs: README.md (the commands), docs/qubit-types.md (the design and what the checker cannot say), docs/m2-results.md (what was refused and what was not), docs/m3-results.md (determinism).

Noise Two ways to simulate it: sampled runs, and the exact density matrix.


    
  
  • Noise, checked against the exact answer
    
      
    Five channels (bit flip, phase flip, depolarizing, amplitude damping, two-qubit depolarizing), readout error and a gate-noise model, each run as one random operator per run. One run is one noisy outcome; the average of many is the density matrix. Here a Bell pair through depolarizing noise on one qubit: 2000 seeded runs per point against the exact curve (1 − p). The largest gap is 0.9 standard errors. 8 noisy circuits (up to 3 qubits) were compared to a density-matrix calculation over 4000 runs each: worst z-scores 0.6, 1.0, 0.1, 1.2, 1.4, 1.3, 1.4, 3.1. Readout error, which flips the reported bit and not the state, is checked as a binomial (z = 1.1 on measured bits, 0.1 on samples, 0.8 when asymmetric). Doubling a probability on purpose is caught at z = 28.0.
    
      
      
    Channels Check Results

  • Exact noise: the density matrix
    
      
    dm 2 keeps the whole density matrix, so one run is the exact answer, not a sample. The same Bell pair through depolarizing noise (p = 1/4) has purity 0.583333 and trace 1.000000; the formula (1−p)² + p²/3 gives 0.583333. The curve is the purity against p: cancho, Qiskit and the formula agree to 8e-16. 20 density-matrix circuits (all channels, every gate, measurement) match Qiskit’s DensityMatrix. Up to 10 qubits: the matrix is stored as a state of twice as many.
    
      
      
    Source Circuits Results

  • A device-style noise profile
    
      
    A JSON file describes a device: a depolarizing rate per qubit for one-qubit gates, per pair for two-qubit gates, and asymmetric readout error per qubit (a true 1 is misread more often than a true 0). scripts/noise_profile.py turns it into 12 operations and puts them in front of a circuit; qsim still reads only standard input. Below, a 5-qubit GHZ state through example-5q (invented numbers of a realistic size, not a real machine) on the density matrix: fidelity 0.9648, purity 0.9308. The bars are the exact outcome probabilities (readout error acts on top, when measuring). It matches a Qiskit calculation made from the JSON to 1e-12.
    
      
      
    Profile Converter Check Format

  • Idle noise: T1 and T2
    
      
    A qubit that waits decays. coher q T1 T2 gives it coherence times in nanoseconds; wait q ns idles it, and time1 / time2 make every gate take time, during which its qubits relax too. The channel is amplitude damping plus dephasing, sampled by trajectories or exact on the density matrix. Below, T1 = 50 µs and T2 = 70 µs: the chance a qubit is still 1, and the coherence of |+⟩, against waiting time. cancho, Qiskit Aer’s own thermal-relaxation channel and the formulas agree to 1e-15. 10 idle-noise circuits match Qiskit; a sampled GHZ circuit with gate times matches the exact density matrix within statistics. Only the gate’s own qubits relax: there is no schedule, so a qubit that waits for others does not decay.

Refused: mistakes the checker catches

  
Each is a real fixture; the red line is the compiler's own message and the tag under the title is the rule.


    
  
  • No cloning
    
      
    Measuring the same qubit twice. The first measure consumes it.
    linear-use-after-move
    
      
    `q` has already been consumed; a `res` value is used exactly once
    
      
    Fixture

  • No dropping
    
      
    A gate borrows the qubit and hands it back, so the function still owes a consumption.
    linear-value-unconsumed
    
      
    `q` is still live here; a `res` value must be consumed on every path
    
      
    Fixture
    

    • 
  
  • Measurement collapses
    
      
    After measure there is no qubit left to borrow.
    linear-use-after-move
    
      
    `q` has already been consumed; there is nothing left to borrow
    
      
    Fixture
    

    • 
  
  • No escaping a borrow
    
      
    A reference to a qubit may not outlive the block that borrowed it.
    reference-escapes-region
    
      
    this returns a reference into `r`, which is a `borrow` block in this function; a reference may not outlive its region
    
      
    Fixture

  • One measurement per qubit
    
      
    measure inside a loop consumes on the first pass and has nothing on the second.
    linear-value-unconsumed
    
      
    `q` is consumed inside this loop; the next iteration would use it again

  • One gate at a time
    
      
    No second unique borrow of a qubit while a gate on it is in flight.

    The index of an owned qubit cannot be read out of it.

Accepted, and should not be

  
Pinned as passing fixtures so that the day a rule refuses them, the build goes red.


    
  
  • CNOT with one qubit as both operands
    
      
    Accepted by the checker (compiles: yes), because a unique borrow is a copyable pointer. It stops at run time instead, with a trap (signal 4, SIGILL, on Linux). Two more ways to the same program are pinned the same way: a copied handle, and two qubits with the same index.
    
      
    Fixture Why
    

    • 
  
  • Forging a qubit
    
      
    A pub res struct can be built and taken apart from any module, so “only fresh makes qubits” is a convention. The page does not hide this: it is a request to the compiler, not a flaw of the simulator.
    
      
    Fixture

Planned

  
Not built, and not promised for any date. Each tile says what is missing.


    
  
  • A Qpu capability Needs the compiler
    
      
    Which backend a program can reach and how many shots it may spend, readable from the program text before it runs. Needs compiler work; shot budgets are only decidable for constant counts, so the honest claim is a declared bound a supervisor enforces.
    
      
    Tracked in cancho#612 Plan
    

    • 
  
  • Refuse CNOT(q, q) at check time Needs the compiler
    
      
    A same-place-twice rule would close at least one of the three ways; its design predicts a second, which is not measured, and says the third needs a different fix. Written, not built.
    
      
    Tracked in cancho#610 Design PR #608
    

    • 
  
  • Private constructors Needs the compiler
    
      
    So that only the simulator can mint a qubit. A proposed opt-in opaque struct; written, not built.
    
      
    Tracked in cancho#611 Design PR #608
    

    • 
  
  • The rest of OpenQASM Planned
    
      
    Decimal angles (their digits are rounded, so they are refused today), gate definitions, u3, if, and writing QASM from cancho itself (a Python script writes it now).
    
      
    Reader
    

    • 
  
  • Scheduled noise and crosstalk Planned
    
      
    Idle noise (T1, T2) exists, but only for the qubits a gate touches and an explicit wait: there is no scheduler, so a qubit that waits while others work does not decay. Noise that depends on the gate type, crosstalk and non-Pauli two-qubit noise are not built.
    
      
    Idle noise
    

    • 
  
  • A real device's calibration Planned
    
      
    Reading a real machine's published error rates into a profile. The example profile is invented; no real calibration data has been used.
    

    • 
  
  • Density matrices past 10 qubits Later
    
      
    The density matrix is stored as a state of 2n qubits, so the 20-qubit limit means 10. Larger needs a different representation.
    

    • 
  
  • A second reference, Cirq Planned
    
      
    Qiskit is the only reference so far. A second one would catch a convention both share.
    

    • 
  
  • Real arm64 hardware Planned
    
      
    The aarch64 result is emulation. A run on a real arm64 machine is still owed.
    
      
    Results
    

    • 
  
  • A cloud quantum service Later
    
      
    Submit a circuit over HTTPS. The authority report will be coarser here, because host-set bounds are design-only in cancho.
    

    • 
  
  • Adjoint and controlled gates Not possible yet
    
      
    Not possible today: cancho has no function values, so a gate cannot be passed to a transform. Circuits stay data.
    

    • 
  
  • A GPU backend Out of scope
    
      
    Out of scope until cancho-gpu exists. A state vector of 20 qubits is fine on one CPU core.
